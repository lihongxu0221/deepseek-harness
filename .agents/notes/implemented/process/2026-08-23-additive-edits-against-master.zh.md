# Agent Note: 相对 master 只做加法修改

Status: implemented

[English](2026-08-23-additive-edits-against-master.md) | 中文

## Problem

在功能分支上工作的 agent（智能体）会重命名或删除默认分支上已有的文件和标识符。这些改动会破坏已经落到 `master` 上的调用方，放大合并冲突，并颠倒本仓库的扩展点模型：新行为应当以新增方法或插件的形式出现，而不是替换已有名称。

若字面禁止编辑 `master` 上已有的任何文件，这条规则也无法成立，因为新增方法必须写入该文件。

## Decision

默认分支是 `master`。已存在于该分支的文件必须保持路径不变。该文件已经声明的方法、参数名和变量名必须保持原名，且不得删除。允许新增方法。允许新增文件。

已有方法的方法体、签名、参数和局部变量名保持 `master` 上的原样。新行为放到新方法、新文件，或不需要改动被冻结方法的既有扩展点中。

对 `master` 路径，以下编辑仍然允许：

- 新增方法所需的方法、类型、常量、导入和 JSDoc
- 在同一路径重新生成由其所属源维护的产物
- 更新用于描述所允许加法改动的测试、快照和文档
- 对 `vendor/` 遵循[Vendoring policy](../../../../AGENTS.md#vendoring-policy)
- 当前用户请求明确授权的改动，包括对本条 standing order 本身的编辑

[预发布立场](../../../../AGENTS.md#pre-release-stance-foundation-over-blast-radius) 仍然拒绝旧的磁盘和 wire 格式。它不授权重命名或删除 `master` 上的源文件或标识符。

## Alternatives considered

**禁止编辑 `master` 上已有的任何文件。** 新增方法必须修改该文件。这条禁令会使已允许的例外无法执行。

**只冻结已导出的公开 API。** standing order 点名的是方法、参数名和变量名，而不仅是导出。若只冻结公开 API，调用方和测试已经依赖的内部标识符仍会被悄悄重命名。

**把协调一致的基础重命名当作常规例外。** 这类例外正是本规则要阻止的源码扰动。只有当前用户请求明确授权时，才可以重命名或删除 `master` 上的文件或标识符。

**只要名称不变，就允许改已有方法体。** 改方法体仍会改变既有调用点的行为，并仍会与针对同一方法的并行工作冲突。新方法可以让这些调用点保持稳定。

## Consequences

功能工作优先新增方法和新文件。必须改动被冻结方法的缺陷修复需要用户明确提出请求。诸如[裁剪无用公开 API](../../proposed/simplification/2026-07-04-prune-dead-core-spine-api.zh.md) 的删除提案在获得此类授权前保持为提案。合并冲突会集中在新增区域，而不是被重命名的标识符上。
